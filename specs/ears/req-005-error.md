# req-005-error: エラーハンドリング

## 概要

API エラー・ネットワークエラー・レート制限エラーを適切に処理する機能。

---

## 要件一覧

### 常時型 (Ubiquitous)

- **req-005-001**: システムは、すべての API エラーをユーザーフレンドリーなメッセージで表示しなければならない

### イベント駆動型 (Event-driven) — WHEN

- **req-005-002**: エラーが発生したとき、システムは error.tsx（Next.js Error Boundary）でエラー画面を表示しなければならない
- **req-005-003**: GitHub API から 403 レスポンスが返却されたとき、システムは「API レート制限に達しました。しばらく待ってから再試行してください。」というメッセージを表示しなければならない
- **req-005-004**: GitHub API から 422 レスポンスが返却されたとき、システムは「検索クエリが無効です。別のキーワードで試してください。」というメッセージを表示しなければならない
- **req-005-004b**: GitHub API から 422 レスポンスかつエラー内容がページ上限超過（"Only the first 1000 search results are available"）のとき、システムは「表示できるのは上位1000件（20ページ）までです。」というメッセージを表示しなければならない
- **req-005-005**: ネットワークエラーが発生したとき、システムは「ネットワークエラーが発生しました。接続を確認してください。」というメッセージを表示しなければならない
- **req-005-006**: 予期しないエラーが発生したとき、システムは「予期しないエラーが発生しました。」というメッセージを表示しなければならない

### 望ましくない動作型 (Unwanted Behavior) — IF

- **req-005-007**: GitHub API の X-RateLimit-Remaining ヘッダーが 0 なら、システムはレート制限リセット時刻を表示しなければならない
- **req-005-008**: エラーメッセージにスタックトレースや内部エラー詳細が含まれるなら、システムはそれらをユーザーに露出させず汎用メッセージに置き換えなければならない
- **req-005-009**: API エラーがコンソールのみへの出力で処理されるなら、システムはユーザーへのエラー通知も合わせて行わなければならない
