# req-004-pagination: ページネーション

## 概要

検索結果の複数ページをナビゲートする機能。

---

## 要件一覧

### 常時型 (Ubiquitous)

- **req-004-001**: システムは、現在のページを URL の `page` パラメータで管理しなければならない
- **req-004-002**: システムは、ページネーションコンポーネントを検索結果一覧の下部に表示しなければならない
- **req-004-003**: システムは、`page` パラメータのデフォルト値を 1 としなければならない
- **req-004-004**: システムは、GitHub Search API の制約により最大1000件（20ページ）までをページネーション対象としなければならない

### イベント駆動型 (Event-driven) — WHEN

- **req-004-005**: ユーザーが「次のページ」をクリックしたとき、システムは URL の `page` パラメータをインクリメントしなければならない
- **req-004-006**: ユーザーが「前のページ」をクリックしたとき、システムは URL の `page` パラメータをデクリメントしなければならない
- **req-004-007**: ユーザーが特定のページ番号をクリックしたとき、システムは URL の `page` パラメータをそのページ番号に変更しなければならない
- **req-004-008**: 検索クエリが変更されたとき、システムは `page` パラメータを 1 にリセットしなければならない

### 状態駆動型 (State-driven) — WHILE

- **req-004-009**: 1ページ目の間、システムは「前のページ」ボタンを無効化しなければならない
- **req-004-010**: 最終ページの間、システムは「次のページ」ボタンを無効化しなければならない

### 望ましくない動作型 (Unwanted Behavior) — IF

- **req-004-011**: `page` パラメータが不正な値（数値以外・0以下）なら、システムは 1 ページ目を表示しなければならない
- **req-004-012**: ページネーション状態を URL 以外で管理しようとするなら、システムは URL パラメータへの置き換えを強制しなければならない
- **req-004-013**: 総件数が1000件を超えるなら、システムはページネーションを最大20ページに制限し「GitHub API の制約により、表示できるのは上位1000件までです」と注記しなければならない
- **req-004-014**: `page` パラメータが20を超えるなら、システムは20ページ目にリダイレクトしなければならない
