# req-001-search: リポジトリ検索

## 概要

GitHub Search API を使用してリポジトリをキーワード検索する機能。

---

## 要件一覧

### 常時型 (Ubiquitous)

- **req-001-001**: システムは、検索クエリを URL の `q` パラメータで管理しなければならない
- **req-001-002**: システムは、検索クエリを Zod でバリデーションしなければならない（1〜256文字）
- **req-001-003**: システムは、検索クエリを `encodeURIComponent` でエンコードしなければならない
- **req-001-004**: システムは、検索フォームを常に画面上部に表示しなければならない

### イベント駆動型 (Event-driven) — WHEN

- **req-001-005**: ユーザーが検索キーワードを入力して検索ボタンを押下したとき、システムは URL を `/?q={keyword}` に変更しなければならない
- **req-001-006**: ユーザーが検索ボタンを押下したとき、システムは GitHub Search API にリクエストを送信しなければならない
- **req-001-007**: ユーザーが検索フォームで Enter キーを押下したとき、システムは検索を実行しなければならない
- **req-001-008**: URL の `q` パラメータが変更されたとき、システムは検索結果を再取得しなければならない

### 状態駆動型 (State-driven) — WHILE

- **req-001-009**: 検索中の間、システムはローディングインジケータを表示しなければならない
- **req-001-010**: 検索フォームが空の間、システムは検索ボタンを無効化しなければならない

### 望ましくない動作型 (Unwanted Behavior) — IF

- **req-001-012**: 検索クエリが256文字を超えるなら、システムはバリデーションエラーを表示しなければならない
- **req-001-013**: GitHub API トークンがクライアント側に露出しそうなら、システムはトークンをサーバー側でのみ使用しなければならない
- **req-001-014**: 検索状態をクライアントグローバルストアで管理しようとするなら、システムは URL パラメータで代替しなければならない
- **req-001-015**: NEXT_PUBLIC_ 接頭辞の環境変数で API トークンを扱おうとするなら、システムはサーバー専用の環境変数を使用しなければならない

### オプション型 (Optional) — WHERE

- **req-001-016**: URL に `q` パラメータが存在する場合、システムは初期表示時に検索を自動実行しなければならない
