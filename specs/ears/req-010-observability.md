# req-010-observability: オブザーバビリティ（非機能要件）

## 概要

リクエストトレーサビリティとサーバーサイドロギングに関する非機能要件。
すべてのリクエストを一意の requestId で追跡し、pino による構造化ログを記録する。

---

## 要件一覧

### 常時型 (Ubiquitous)

- **req-010-001**: システムは、すべての HTTP リクエストに一意の requestId（UUID v4）を生成し、`x-request-id` ヘッダーとして付与しなければならない
- **req-010-002**: システムは、すべてのサーバーサイドログエントリに `requestId` フィールドを含めなければならない
- **req-010-003**: システムは、ログを JSON 形式（pino）で出力し、`service: "github-repository-search"` フィールドをすべてのエントリに付与しなければならない
- **req-010-004**: システムは、`LOG_LEVEL` 環境変数でログレベルを制御し、未設定時のデフォルトを `"info"` としなければならない

### イベント駆動型 (Event-driven) — WHEN

- **req-010-005**: GitHub API リクエストが送信されたとき、システムは URL・HTTP ステータスコード・requestId をログに記録しなければならない
- **req-010-006**: GitHub API から 403 レスポンスが返却されたとき、システムは `warn` レベルでレート制限ログを記録しなければならない
- **req-010-007**: GitHub API から 4xx/5xx エラーが返却されたとき、システムは `error` レベルでエラーログを記録しなければならない
- **req-010-008**: クライアントサイドエラーが発生したとき、システムは Server Action 経由でサーバーログに `error` レベルで記録しなければならない

### 望ましくない動作型 (Unwanted Behavior) — IF

- **req-010-009**: requestId が取得できない場合、システムは `"unknown"` をフォールバック値として使用しなければならない
- **req-010-010**: スタックトレースや内部エラー詳細をレスポンスボディに含めようとするなら、システムはそれをログにのみ記録し、ユーザーには汎用メッセージを返さなければならない
